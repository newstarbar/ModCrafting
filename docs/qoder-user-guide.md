# 在 Qoder 中制作 Minecraft 模组

适用：Windows、Qoder 国际版桌面、Minecraft Fabric 1.21.4。更新：2026-10-18。

## 开始使用

安装插件后新建聊天，选择 ModCrafting Fabric，然后直接描述你的想法，例如：

- “我第一次用，带我开始做模组。”
- “帮我做一个可以吃的蓝莓，打开页面让我调整属性。”
- “给这个物品加一个合成配方。”
- “打开游戏，检查这个物品能不能正常获得。”

助手会检查当前文件夹和运行环境。空文件夹可以用来新建工程；已有工程会继续使用。可视化创作时，助手应调用插件的打开功能，把当前工程带到浏览器对应编辑页面。自动打开失败会提供可点击的链接。

页面与聊天共用同一份工程；每个任务聊天使用独立 session，运行记录和报告按任务隔离。请使用当前聊天返回的链接；不要手工另起服务或复用其他任务的旧链接。首次介绍不会自动下载全部知识资料，也不会启动游戏。

工作台采用左侧模块导航和单一主区域：一次只显示当前任务需要的内容、贴图、配方、界面、模型、构建、游戏、测试或报告。Agent 可推荐对应模块；你手动切换页面后会暂停自动跟随，可以随时点“跟随 Agent”恢复。结束的任务可以切换到只读模式查看报告。

## 你可以做什么

| 你想做的事 | 可以怎么说 |
| --- | --- |
| 新建模组 | “在当前空文件夹创建一个模组，名字叫蓝莓工坊。” |
| 制作物品、食物、方块或装备 | “给这个物品调整堆叠数量，打开编辑页面。” |
| 编辑合成配方 | “用木棍和铁锭合成这个物品，让我看看配方。” |
| 制作游戏界面 | “做一个按快捷键打开的设置页面。” |
| 制作 3D 模型 | “用体素模型做一个发光的灯柱方块，让我在模型页调整。” |
| 打包或检查效果 | “打包模组”“启动游戏检查新物品”。 |

页面中的预览用于调整设计。保存后还需要重新打包、启动游戏，才能确认真实效果。部分游戏行为暂时不能自动判断，助手会解释哪些已经确认、哪些仍需手动检查。

## 安装与更新

1. 在 Qoder“扩展 → 插件 → 添加插件 → 上传 Plugin”选择完整 ZIP，确认 ModCrafting Fabric 已启用。
2. 更新后重新连接并新建聊天。旧聊天可能仍连接旧后端。
3. 以前单独添加过 ModCrafting 连接器时，保留其配置和数据，只启用一个来源，避免连到不同后端。

本轮本地候选版本：`0.1.5`，承接上一轮 `0.1.4` 并递增补丁号（版本号语义见 AGENTS.md：Z=本地验证更新、Y=GitHub 发行版变更、X=大版本更新），避免宿主把新增的 AI 3D 体素模型工作区当成同版缓存。这是本地候选，没有远端发布或正式版本标签。完整包包含三份技能、三个命令和 28 个工具，以及配套的第二版游戏测试组件。游戏启动时自动应用组件，无需自行下载或替换 JAR。

插件支持的 Minecraft 目标仍是 1.21.4；“插件版本”“Minecraft 版本”和“游戏测试组件版本”分别显示，不能互相替代。

## 游戏测试设置与启动

新任务先创建一个任务会话；之后构建、启动、状态、测试、停止与报告都沿用返回的 sessionId。继续旧任务时显式恢复该 session。

默认测试配置为简体中文、1280×720 窗口、视距 8、60 FPS、30% 音量、旁白关闭；地图默认平地、种子 0、创造模式、和平难度并允许测试命令。设置只作用于当前会话。只有你明确勾选“保存为此工程默认”才会写入工程配置；游戏运行中修改的值会在下次启动应用。

启动游戏会自动处理 Minecraft 首次无障碍提示并创建或读取会话专属的 `ModCrafting Test World`。也可以选择复制已有存档：原存档只读，配置只应用到会话副本。客户端启动、桥接连接和测试世界就绪是三种状态；请等工作台显示“可以开始测试”（`canRunTests=true`）后再验证。准备失败时会显示所处阶段、当前界面和建议操作，不要反复重启。

## 文件会放在哪里

模组源码和构建结果位于你选择的工程目录。知识资料、报告和默认构建缓存位于插件的数据目录；若已显式设置 GRADLE_USER_HOME，则继续使用该位置。环境检查会报告实际路径。

需要放在 D/F 盘时，应给插件配置该盘的可写数据目录，重新连接后确认路径，再开始下载或构建。插件不迁移或删除旧缓存，也不控制 Qoder 自己的安装、聊天、模型或插件缓存。

首次构建可能需要下载 Gradle 和依赖。知识资料按需准备，已有健康资料会复用。插件不自动安装 Java；需要 JDK 21。明确设置了 JAVA_HOME 时优先使用它，否则从 PATH 查找，并把确认后的 Java 位置传给构建进程。

## 遇到问题

| 提示或现象 | 下一步 |
| --- | --- |
| 当前还没有模组工程 | 在空文件夹里描述要创建的模组，或选择已有工程。 |
| 浏览器没有自动打开 | 点击当前聊天给出的完整工作台链接。不要删掉链接后的内容。 |
| 页面连不上 | 重新连接插件并取新链接，确认聊天与页面来自同一后端。 |
| Java 不可用 | 安装/选择 JDK 21，检查 JAVA_HOME 后重新连接。 |
| 游戏测试组件版本不匹配 | 停止该测试游戏，更新完整插件，再从插件启动；不要反复调用旧接口。 |
| 保存冲突或只读 | 保留草稿，让助手比较外部改动；不要强行覆盖手写文件。 |
| 游戏打开了，但功能还不能确认 | 查看实际启动状态、进入专用测试世界，区分“游戏启动”和“功能通过”。 |
| Qoder 显示 Hook 失败或操作被拒绝 | 这是宿主提供的消息，需要按原始原因处理；不要让插件绕过宿主限制。 |

## 给插件开发者

在完整 Core/MCP 源码工作区，使用系统 JDK 21 构建配套组件，然后打包：

```powershell
Push-Location bridge-mod
.\gradlew.bat build --no-daemon
Pop-Location
node scripts/plugin/build.mjs --observer-jar bridge-mod/build/libs/modcrafting-observer-2.0.0.jar
node scripts/plugin/stage.mjs
pnpm run plugin:qoder --source "D:/your-checkout/temp/plugin-artifacts/modcrafting-fabric"
```

单独的纯 Node plugin:build 可以生成开发后端，但不包含游戏组件，Qoder 完整打包会拒绝该产物。也可用 candidate:build 从同一源码构建完整多宿主候选。Bench 的独立运行使用产品内的 observer/manifest.json 和匹配 JAR；源码运行可指定 --observer-dir。

打包器检查 compatibility.json 中的版本、Minecraft 目标、组件协议及后端 SHA-256，再输出新目录、ZIP 和文件清单。默认使用 QODER_PLUGIN_ROOT/QODER_PLUGIN_DATA；--data-root、--node、--gradle-home 可生成机器专用配置包，显式复用旧资源及已有构建缓存，不依赖宿主是否继承变量。生成器不安装插件、不修改真实 Qoder 设置。

参考：[Qoder 官方插件文档](https://docs.qoder.com/qoder/plugins)、[插件结构参考](https://docs.qoder.com/cli/plugins-reference)、[Gradle 环境配置](https://docs.gradle.org/current/userguide/build_environment.html)。

本地后端回归、浏览器检查、Qoder 组件加载和真实模型聊天是不同证据。具体本轮验证结果与未验证范围见仓库归档，不把工具发现成功当作真实模组验收。
