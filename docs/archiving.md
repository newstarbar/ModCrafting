# 归档机制

ModCrafting 项目要求 AI Agent 在合适时机自动归档本次工作成果到 `docs/archive/` 目录，形成项目知识库沉淀。

## 触发时机

AI Agent 必须在以下三种场景下主动触发归档流程：

### 1. 开发者主动触发

当开发者明确说出包含"归档"、"archive"、"记录到知识库"、"沉淀经验"、"总结到文档"等关键词的指令时，立即归档。

**识别关键词（包含即可）**：
- 归档、archive（不区分大小写）
- 沉淀、记录到知识库
- 写入文档、写到 docs
- 总结到文档、保存经验

### 2. 大功能改动自动触发

当一个会话内完成了以下任一类型的大改动，**在工作完成时主动归档**（无需用户提醒）：

- 新增模块或核心文件（≥3 个新文件且属于核心功能）
- 重构现有模块的核心逻辑（如修改主流程、调整架构）
- 修复复杂 bug（涉及多个文件、根因非显而易见）
- 调整 AI Agent 行为规则（如计划阶段门控、工具白名单、护栏机制）
- 添加或修改构建流程、工具链、知识库构建逻辑

### 3. 繁琐问题解决后提醒

当一个复杂问题（多轮调试、多次失败重试、涉及深层根因）被解决后，在最终总结中**主动提醒**开发者：

> 这次问题排查较复杂，涉及 [X] 个文件、[Y] 次失败。建议执行「归档」将本次经验沉淀到本地知识库，便于未来遇到同类问题时快速定位。

提醒后**等待开发者明确指示**，不擅自归档。

## 归档流程

### 命名规范

```
docs/archive/YYYY-MM-DD-<kebab-case-title>.md
```

- 日期：使用当天日期（Asia/Shanghai 时区）
- 标题：简短描述本次工作主题，kebab-case，避免过长（建议 ≤6 个单词）
- 同一天有多个归档时，文件名末尾加 `-1`、`-2` 等序号

**示例**：
- `2026-07-28-fix-frame-cover-and-harness-exploration.md`
- `2026-07-28-add-knowledge-base-vector-search.md`
- `2026-07-29-refactor-agent-controller.md`

### 归档模板

```markdown
# <标题>

**归档日期**：YYYY-MM-DD
**触发方式**：开发者主动 / 大功能自动 / 提醒后归档
**涉及文件数**：N
**问题类型**：bug 修复 / 新功能 / 重构 / 配置调整 / 文档

## 背景

<本次工作的背景：用户反馈、问题描述、需求来源>

## 根因分析

<如果是 bug 修复，详细说明根因；否则简述设计思路>

## 改动清单

| 文件路径 | 改动类型 | 说明 |
|---------|---------|------|
| `path/to/file` | 修改 | <简要说明> |
| `path/to/new-file` | 新增 | <简要说明> |

## 关键决策

<记录过程中做出的关键决策与权衡>

## 验证方式

<如何验证本次改动生效：测试命令、手动验证步骤>

## 经验教训

<本次工作有哪些可以复用的经验、踩过的坑、未来同类问题的快速排查路径>
```

### 归档步骤

1. **确认触发**：判断属于哪种触发场景
2. **收集信息**：整理本次会话的改动清单、根因、决策
3. **生成文件**：按模板写入 `docs/archive/YYYY-MM-DD-<title>.md`
4. **更新索引**：在 `docs/archive/README.md` 中追加一行条目
5. **同步 project_memory**（可选）：如果是值得跨会话保留的规则，同步更新 `.trae-cn/memory/projects/-d-project-file-Full-stack-ModCrafting/project_memory.md`

## 归档目录结构

```
docs/
├── archive/
│   ├── README.md              # 归档索引（按时间倒序）
│   ├── 2026-07-28-<xxx>.md    # 单次归档文件
│   └── ...
```

## 索引格式

`docs/archive/README.md` 每个条目格式：

```markdown
- [YYYY-MM-DD] **标题** — 一句话描述。触发：主动/自动/提醒。
```

示例：
```markdown
- [2026-07-28] **修复 Frame Cover 与 Harness 勘探限制** — SideMenuTitleScreen 点击、ScreenshotHandler 连续截图、计划阶段门控放宽。触发：开发者主动。
```

## 注意事项

- **不擅自归档**：除了大功能改动自动触发外，其余场景需用户明确指示
- **简洁有用**：归档不是流水账，重点写"根因"和"经验教训"，未来读者能快速定位问题
- **避免重复**：如果同主题已有归档，在原文件末尾追加"更新"章节而非新建文件
- **保持索引同步**：每次新增归档后必须更新 `docs/archive/README.md`
- **敏感信息脱敏**：不写入 API Key、用户路径、个人凭证
