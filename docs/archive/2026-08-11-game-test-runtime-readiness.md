# 游戏测试运行时依赖与假就绪修复

## 事故链

2026-08-11 的真实 Minecraft 会话中，Fabric 已加载目标模组 `my-mod`，但未加载 Mod Menu 或 ModCrafting Observer。游戏测试仍把“进入主菜单”当作启动成功，随后反复尝试进入测试世界并因桥接不存在失败。

根因是三层契约同时失效：下载 ZIP 保留顶层目录而下载器又解压到同名目录；基础模组同步器只检查目录存在；主进程桥接代理只放行 `/v1/*`，使已加载的 Observer V2 也无法执行 V2 游戏测试。

## 修复策略

- 下载器规范化平铺与历史同名嵌套目录，并以内容而非目录存在性判断七类知识库/辅助产物是否就绪。
- 基础模组按 `fabric.mod.json` 的 ID 验证和同步，开发资源优先于旧下载资源；Observer 声明协议版本 2。
- `McRuntimeReadiness` 成为 run 步骤的唯一通过契约：Fabric 模组清单、桥接发现、V2 capabilities 和游戏目录均需可审计。
- `/v1/*` 与 `/v2/*` 都经过本地 Bearer 认证转发；非法路径继续拒绝。
- 环境或协议错误返回 `INCONCLUSIVE`，并由重复守卫收敛，永不触发用户模组代码修复。

## 回归要求

- `MC_PHASE:menu` 不得推进 run 步骤。
- 缺少任一目标、Mod Menu、Observer 或 V2 capability 时不得进入 `game_test`。
- 旧双层基础模组目录可在不重新下载的情况下恢复。
- Test Lab 报告必须保存加载模组、基础模组来源、协议版本和实际游戏目录。
